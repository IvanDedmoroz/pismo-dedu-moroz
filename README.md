# Письмо Деду Морозу — локальная версия

Приложение работает на компьютере владельца и хранит данные в SQLite в папке `data/`. Интернет нужен только Docker для первой сборки контейнера. После запуска сайт открывается на `http://localhost:3000`.

## Запуск в Windows

1. Установи Docker Desktop и дождись, пока он запустится.
2. Распакуй архив в обычную папку, например `C:\PismoDeduMoroz`.
3. Дважды щёлкни `start.bat`.
4. Войди с логином `admin` и выданным отдельно паролем.
5. Чтобы выключить приложение, запусти `stop.bat`.

На первом старте Docker скачает базовый образ и соберёт контейнер. Последующие запуски используют уже собранный образ.

## Учётные записи и доступ

- Первый аккаунт `admin` создаётся автоматически при первом запуске.
- В панели «Участники и доступ» организатор создаёт участникам логины и пароли.
- Каждый пользователь может нажать на значок рядом со своим именем, выбрать один из 20 праздничных аватаров и сохранить его в профиле. Выбор отображается рядом с именами участников в списках; существующие аккаунты автоматически получают пустое значение до первого выбора.
- Во вкладке «Обновления» публикуются заметки о нововведениях, начиная с релиза 20 праздничных аватаров. Участники могут поставить лайк или дизлайк и изменить реакцию; организатор может публиковать новые заметки и видеть число реакций.
- Для каждой пары настраиваются отдельные права: смотреть список и предлагать подарки.
- Участник добавляет желания только в собственный список. Желания можно убрать в личный архив, вернуть из него или удалить навсегда. Архивные записи видит только владелец; у остальных участников они сразу исчезают. Пароли в базе не хранятся в открытом виде.
- У любого участника есть вкладка «Идеи и отзывы»: общие комментарии и предложения можно искать, фильтровать по типу, сортировать и убирать в личный архив. Организатор видит общий архив и может вернуть запись.
- Участник с доступом к чужому желанию может отметить, что готов его подарить. Все видят только число отметок и собственную отметку; имена участников видит только организатор. Для одного желания отметку могут поставить несколько человек.
- Для предложений подарков доступны три режима: все видят имя автора (выбран по умолчанию); все видят текст анонимно; только получатель и организатор видят предложение. В анонимном режиме имя автора не передаётся в браузер участников, но доступно организатору. Общие предложения отображаются под списком получателя и в общей ленте вкладки «Идеи и отзывы». Старые предложения при обновлении базы сохраняются как приватные.
- В матрице доступа можно перетаскиванием менять ширину столбцов и высоту строк. Размеры сохраняются в базе для аккаунта организатора; кнопка «Вернуть исходный вид» сбрасывает их.
- В разделе «Участники и доступ» организатор может скачать резервную копию базы кнопкой «Скачать архив базы». Сервер создаёт согласованный снимок SQLite с учётом WAL и отдаёт сжатый файл `.sqlite.gz` через браузер. Архив включает аккаунты, желания, настройки и журнал; храни его приватно.
- В «Участники и доступ» организатор выбирает одну из четырёх общих тем: мастерская Леонардо, импрессионистская зима, сказочный лубок или Новый год в Москве. В каждой теме своя палитра, типографика и иллюстрация Красной Огненной Козы; на странице входа вместе с темой меняется соответствующая новогодняя открытка. Можно менять тему вручную либо включить случайный выбор раз в сутки по московскому времени; выбранный вариант сохраняется в базе и одинаков для всех участников.
- Если удалить папку `data/`, будут удалены участники, списки, предложения и настройки доступа.

## Первое знакомство с сайтом

На вкладке «Списки желаний» открывается памятка из шести шагов: добавить желание, открыть доступ, выбрать список близкого, отправить предложение, отметить готовность подарить и найти обновления. Памятку можно свернуть; выбор запоминается отдельно для каждого аккаунта в браузере. Вернуть её можно кнопкой «Показать памятку на главной» в разделе «О сайте».

Раздел «О сайте» объясняет, зачем создана семейная новогодняя почта и как устроены списки, предложения и отметки о подарках.

## Telegram-бот: уведомления, просмотр и новые пожелания

Бот отправляет уведомления о публичных предложениях и принимает команды только из группы, чей ID указан в `TELEGRAM_CHAT_ID`. После публикации бот сам добавит в группу меню с кнопками «Посмотреть желания», «Добавить своё желание» и «Мои пожелания», затем попробует закрепить его. Если у бота нет права закреплять сообщения, меню появится в группе, а закрепить его сможет администратор вручную.

Чтобы добавить пожелание, участник нажимает «Добавить своё желание», затем пишет текст в ответ на подсказку бота. Команды можно не вводить.

В группе также доступны команды:

- `/wishes@MyProbaPera_bot` — показать все активные желания зарегистрированных участников сайта. Архивные желания не включаются. Этот ответ доступен всем участникам Telegram-группы независимо от матрицы доступа сайта.
- `/wish@MyProbaPera_bot текст` — добавить пожелание от своего Telegram-профиля без регистрации на сайте и без связывания аккаунтов. Сообщение команды и пожелание будут видны в группе.
- `/mywishes@MyProbaPera_bot` — показать свои пожелания, отправленные через Telegram.
- `/deletewish@MyProbaPera_bot номер` — удалить своё пожелание по номеру из ответа `/mywishes`.
- `/help@MyProbaPera_bot` — показать команды.

Пожелания, созданные в Telegram, отображаются на сайте в отдельном блоке «Пожелания из Telegram» и видны всем пользователям сайта. Организатор может удалить запись на сайте; автор — командой `/deletewish номер`.

Для работы укажи в Blitz → Environment:

- `TELEGRAM_BOT_TOKEN` — токен от `@BotFather`.
- `TELEGRAM_CHAT_ID` — числовой ID группы, включая минус.
- `PUBLIC_APP_URL` — публичный HTTPS-адрес сайта, например `https://pismo-dedu-moroz.dedmoroz.blitz.cloud`.
- `TELEGRAM_WEBHOOK_SECRET` — секрет длиной от 16 до 256 символов: только латинские буквы, цифры, `_` или `-`. Сгенерируй отдельное случайное значение и не публикуй его.

После публикации кода и перезапуска приложение автоматически зарегистрирует защищённый webhook, команды и сообщение с кнопочным меню. В журнале запуска появится `Telegram bot commands are ready.` Для проверки нажми в меню «Посмотреть желания» или «Добавить своё желание». После настройки webhook метод `getUpdates` больше не используется.

Пожелания, введённые в ответ на подсказку меню в группе, будут видны всем её участникам. Через Telegram создаётся отдельная запись, не связанная с одноимённым аккаунтом сайта. Ограничение — пять новых пожеланий в час на Telegram-пользователя.

## Журнал доступа и действий

Организатору доступна вкладка «Журнал действий». В ней сохраняются посещения сайта, успешные и неудачные попытки входа, выходы, создание и удаление участников, смена пароля, изменения матрицы доступа, действия с желаниями, идеи для подарков, записи обратной связи и отметки о готовности сделать подарок. Для записей сохраняются ник, дата и время, IP-адрес и строка браузера; пароль и введённые пароли не сохраняются. Есть поиск, фильтры по типу события и датам, сортировка по времени и постраничный просмотр.

Журнал хранится в `data/wishlist.sqlite`. Для Blitz задай в **Environment** переменную `TRUST_PROXY=1`, чтобы приложение использовало адрес посетителя из заголовков доверенного прокси; изменение переменной применяется после перезапуска. Устанавливай это значение, только когда приложение работает за доверенным прокси, например Blitz. Старые события до установки этой версии в журнал не попадут.

## Где хранятся данные

Все данные находятся в `data/wishlist.sqlite`. Новые таблицы для отзывов, отметок о подарках, размеров матрицы и общих настроек оформления создаются автоматически в существующей базе. Перед обновлением на Blitz сохрани резервную копию и убедись, что папка `/app/data` добавлена в список файлов, которые Blitz сохраняет при перезапуске и выпуске новой версии. Для локальной резервной копии сначала нажми `stop.bat`, скопируй папку `data`, затем снова запусти приложение. Не отправляй папку `data` в общий чат или публичное облако.

По умолчанию сайт привязан только к `localhost`, поэтому другие устройства не смогут открыть его по сети. Не открывай порт 3000 в интернет напрямую. Для внешнего доступа понадобится отдельная настройка HTTPS и обратного прокси; сейчас версия рассчитана на работу на одном компьютере.

## Смена первичного пароля

Пароль первого администратора задан в скрытом файле `.env`. Если сменить его до первого запуска, будет создан аккаунт с новым паролем. После создания базы изменение `.env` не меняет уже сохранённый пароль.
